# Project Context Core — Progress Evidence

This is a progress artifact for #222 / #167, not final owner acceptance.

## Exact slice exercised

```text
bounded canonical evidence refs
→ project_context_synthesis InferenceTask
→ shared privacy-route policy
→ structured project understanding
→ evidence-identity fingerprint
→ immutable ProjectContextSnapshot
→ browser/memory/store repository
→ later project-scoped Signal resolves latest context
```

## Product invariants covered

- Project facts remain separate from person Identity/Voice.
- Project context has no destination/content-format decision fields.
- Same exact evidence identity reuses the existing context even if a model retry could word the summary differently.
- Meaningful repository revision/evidence changes create an immutable successor instead of rewriting prior context.
- `Not now` does not mutate or discard project context.
- Later project-scoped Signals can resolve prior project context automatically.
- Model input is bounded instead of accepting an unrestricted repository payload.
- Secret/path-shaped fields fail closed.
- Device-private/restricted context cannot silently use a remote model route.

## Current bounded synthesis limits

- maximum evidence items: 24;
- maximum aggregate evidence text: 60,000 characters;
- exact SourceArtifact IDs remain inference refs;
- accepted evidence categories are explicit and source-neutral.

## Explicit non-claims

This branch does **not** yet prove:

- real GitHub App installation;
- automatic full repository traversal/evidence selection after connection;
- hosted ProjectContext persistence;
- automatic initial Signal/Opportunity suggestion from a connected repo;
- owner-facing first-run onboarding;
- production webhook → context → Opportunity continuation;
- calendar/destination/form recommendation;
- real-repository production acceptance.

Those remain the next vertical integrations. #222 stays open.
